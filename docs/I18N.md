# Interface languages / 界面语言

NodeBridge supports Simplified Chinese and English through Qt `QTranslator`. Choose **View → Language**, and the interface updates immediately. The saved `interface/language` preference overrides the system locale; without a saved preference, Chinese locales use Simplified Chinese and other locales use English. Switching languages preserves live connections and terminal views.

NodeBridge 通过 Qt `QTranslator` 支持简体中文和英文。在“查看 → 语言”中选择，立即生效。保存的 `interface/language` 设置优先于系统语言；未保存选择时，中文系统使用简体中文，其余系统使用英文。选择语言不会断开正在运行的连接或重建终端页面。

## Boundaries / 翻译边界

Translate application-owned display text with `nodebridge.i18n.tr()`. Keep Chinese source strings and stable internal identifiers unchanged. Insert paths, node names and other values **after** translating the template. Do not translate remote terminal output, commands, user-created names or descriptions. Built-in command descriptions may be translated for display without changing saved command data.

应用自身的显示文字使用 `nodebridge.i18n.tr()` 翻译。中文源字符串及稳定的内部标识保持不变；路径、节点名称等值在翻译模板**之后**填入。远程终端输出、命令、用户自建名称和说明不翻译。内置常用命令说明可在显示时翻译，但不修改保存的命令数据。

Persistent activity and diagnostic logs retain their existing source language, independently of the interface. The operation-log view also preserves the original records. External error messages retain their original language. The built-in Chinese user guide remains unchanged. Do not pass translated UI messages into log actions, log results or persistent session states.

活动日志和诊断日志文件保持原来的语言，不随界面切换；操作日志视图也保留原始记录。外部错误信息保持其原始语言。内置中文使用指南保持不变。不得将翻译后的界面文字传入日志操作、日志结果或持久会话状态。

## Updating translations / 更新翻译

Add source/English pairs to `nodebridge/assets/i18n/nodebridge_en.ts`, then run:

在 `nodebridge/assets/i18n/nodebridge_en.ts` 中添加中文源文本与英文译文，然后执行：

```powershell
.\.conda-env\python.exe scripts\update_translations.py
.\.conda-env\python.exe -m unittest tests.test_i18n -v
```

The script checks missing literal `tr()` entries, duplicate sources, unfinished translations and placeholder consistency, then compiles `nodebridge_en.qm`. Variable-based labels require explicit catalog entries and review. Commit both `.ts` and `.qm` so source runs need no compilation step. Portable builds validate and compile the catalog before packaging the assets. `--check` validates without compiling. Existing widget properties are updated in place through explicit display bindings; live sessions and input drafts are preserved.

脚本检查 `tr()` 常量漏译、重复源文本、未完成译文及占位符一致性，再编译 `nodebridge_en.qm`。变量形式的标签需要显式补充词条并人工检查。应同时提交 `.ts` 和 `.qm`，让源码运行无需额外编译；绿色版构建会先检查、编译，再打包资源。`--check` 只检查不编译。通过显式显示绑定原地更新已有控件，保留连接和输入草稿。

Use `ui(widget.setText, tr(...))` or `ui(QLabel, tr(...))` for translated Qt properties. `DisplayText` retains source templates and values; `ui()` binds only explicitly translated values. Plain user text is never reverse-matched against the catalog. Weak references avoid retaining deleted widgets, and setters discard stale bindings when newer content replaces a value. Custom models repaint their display data after a switch. Do not recreate terminal pages or rerun network operations to change language.

翻译 Qt 属性时使用 `ui(widget.setText, tr(...))` 或 `ui(QLabel, tr(...))`。`DisplayText` 保留源模板和参数，`ui()` 只绑定显式翻译的值，不通过反查词典识别普通用户文字。弱引用避免保留已删除的控件，新内容覆盖旧值时撤销过时绑定；自定义模型在切换后重绘显示数据。切换语言不得重建终端页面或重新执行网络操作。
