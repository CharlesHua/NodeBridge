# Architecture / 架构

This document describes the current implementation and explicitly labeled future architecture. The roadmap is in [TODO.md](TODO.md); [CURRENT_STATUS.md](CURRENT_STATUS.md) separates implemented and planned behavior.

本文描述当前实现及明确标注的未来架构。路线图见 [TODO.md](TODO.md)；[CURRENT_STATUS.md](CURRENT_STATUS.md) 区分已实现与计划中的功能。

## Components / 组件

`nodebridge/__main__.py` starts `app.py`, which creates the Qt application and `MainWindow` in `window.py`. The main window owns the primary remote session, a stack of previous jump sessions, separate work-node sessions, the file panes, and the current background job. Its Files and Terminal tabs switch between `worker_browser.py` and `terminal_workspace.py`. The latter displays the node tree, terminal tabs, and explicit Terminal Groups with selected broadcast recipients. `terminal_session.py` owns live shell channels outside the widgets and polls them for output. `local_browser.py` provides the local directory tree and file list; `drag_drop.py` translates Qt drag data into local paths or a NodeBridge remote-session token and paths.

`nodebridge/__main__.py` 启动 `app.py`，由它创建 Qt 应用及 `window.py` 中的 `MainWindow`。主窗口持有主远程会话、前级跳板会话栈、独立的工作节点会话、文件面板及当前后台任务。“文件”和“终端”标签页分别呈现 `worker_browser.py` 和 `terminal_workspace.py`。后者显示节点树、终端标签及明确的 Terminal Group 和广播接收目标。`terminal_session.py` 在界面组件之外持有实时 Shell 通道，并轮询接收输出。`local_browser.py` 提供本地目录树和文件列表；`drag_drop.py` 将 Qt 拖动数据转换为本地路径，或 NodeBridge 的远程会话标识和路径。

The terminal node tree includes discovered aliases independently of Files-tab worker SFTP sessions. `RemoteSession.open_alias_shell` opens a PTY through the jump transport without first opening worker SFTP. `TerminalManager` retains these channels when a worker's Files-tab connection closes, and closes them when their jump connection closes. Node batch checkboxes choose which terminals to open or close; broadcast recipients are chosen separately in the active group's member list. Both file and terminal node trees use the small shared `node_check_tree.py` widget for Shift range selection. Opening several terminals uses a bounded thread pool inside one top-level job.

终端节点树独立于文件页工作节点 SFTP 会话，包含已发现的别名。`RemoteSession.open_alias_shell` 通过跳板传输通道直接打开 PTY，无需先打开工作节点 SFTP。文件页关闭某工作节点连接时，`TerminalManager` 保留其终端通道；跳板连接关闭时才关闭。节点的批量勾选决定要打开或关闭哪些终端；广播目标则在当前组成员列表中单独选择。文件与终端的节点树共用小型 `node_check_tree.py` 控件实现 Shift 连续勾选。一次打开多个终端时，在一个顶层任务内使用有限线程池。

Broadcast targets are snapshotted as one selected session per node from the active group. `MainWindow` sends an OSC-marked `pwd -P` probe to idle, recognizable Shell prompts and buffers each probe's output until its marker arrives. Different or unknown directories require explicit confirmation before the command is sent to each target through `TerminalManager`; common destructive Shell commands require another confirmation. Each terminal retains its own output. The send status does not track remote command exit codes.

广播目标在发送时固定为当前组内每个选中节点的一个终端。`MainWindow` 对可识别且空闲的 Shell 提示符发送带 OSC 标记的 `pwd -P` 探针，并缓存输出直到收到标记。目录不同或未知时先要求明确确认；常见破坏性 Shell 命令还需额外确认。随后通过 `TerminalManager` 向各目标发送命令；每个终端保留自己的输出。发送状态不跟踪远程命令退出码。

The probe's echoed command and returning prompt are filtered before terminal rendering. The broadcast controls are below the terminal area. A group's editable name is separate from its generated, abbreviated node suffix, and each terminal tab begins with its group name. After an approved broadcast, `TerminalWorkspace` records each recipient's document position at its visible prompt. The read-only combined view concatenates the resulting terminal fragments in natural node order for each broadcast, without adding headings; copying fragments preserves ANSI-derived character formats. A recognized returning Shell prompt marks that node's reply end without copying that next prompt, and a later broadcast bounds any still-open fragment. It does not infer a global execution order or merge identical results.

探针命令回显和返回的提示符会在终端渲染前过滤。广播控件位于终端区下方。终端组可编辑的名称与自动生成、缩写的节点后缀分开，各终端标签以组名开头。广播获准发送后，`TerminalWorkspace` 从每个接收终端当前可见提示符处记录文档位置。只读“联合显示”对每次广播按节点自然顺序直接拼接终端片段，不额外添加标题；复制文档片段可保留 ANSI 渲染后的字色。识别到 Shell 提示符返回时，以该提示符之前为本轮反馈终点；仍未结束的片段以下一次广播为边界。联合视图不推断跨节点的统一执行顺序，也不合并相同结果。

`TerminalOutput.focusNextPrevChild` forwards Tab to the PTY before Qt can use it for focus traversal; the remote Shell performs completion and its BEL sounds locally. The command helper remembers whether the last input focus belonged to the broadcast field or the current live terminal. It replaces the broadcast draft directly, or sends Shell line-editing keys followed by a template to the selected terminal without Enter. After successful delivery, `MainWindow` restores focus to the broadcast field. The combined renderer inserts a blank line only after every recipient in that broadcast round has reached a reply boundary.

`TerminalOutput.focusNextPrevChild` 在 Qt 把 Tab 用于焦点切换前将其转发给 PTY；补全由远程 Shell 完成，其 BEL 在本地响铃。命令助手记住最近获得输入焦点的是广播框还是当前活动终端。它直接替换广播草稿，或向选中的终端发送 Shell 行编辑按键和模板，但不发送回车。成功发送后，`MainWindow` 将焦点还给广播框。联合渲染器仅在本轮所有接收节点均到达反馈边界后插入空行。

## Terminal-group boundary / 终端分组边界

`TerminalGroup` in `terminal_workspace.py` records a stable run-local ID, display name, members, and selected broadcast recipients. Each successful connection batch creates a new group; a single new terminal forms its own group. Group selection and the member list are visible in the Terminal tab. Switching groups clears the draft command; there is no separate broadcast-mode checkbox. `MainWindow` receives the group ID with each broadcast request and validates session membership before the cwd probe and again before delivery. There is no implicit global broadcast. Groups are in memory for this run; remote session persistence remains future work.

`terminal_workspace.py` 中的 `TerminalGroup` 记录本次运行内稳定的 ID、显示名称、成员和已选广播目标。每次成功连接一批节点都会创建新组；单独新建终端也形成自己的组。终端页显示组选择和成员列表。切换组会清空输入；不再设单独的广播模式勾选框。`MainWindow` 收到带组 ID 的广播请求，在目录探针前及实际发送前都校验会话成员关系。没有隐式全局广播。组信息只保存在本次运行的内存中；远程会话持久化仍是后续工作。

For later identical-result compression, retain each terminal's raw output and associate a bounded broadcast command with its group and per-session results. A separate comparison layer may normalize presentation-only differences before grouping effectively identical results; continuously interactive terminal streams must remain individually viewable. The current combined view separates broadcast rounds but does not compare or deduplicate their results.

未来对相同结果的压缩展示应保留每个终端的原始输出，并把一次有明确边界的广播命令关联到所属组和逐会话结果。独立的比较层可在归并实质相同结果前归一化仅影响展示的差异；持续交互的终端流仍需可单独查看。当前联合视图已分开各次广播，但尚不比较或去重结果。

`remote.py` owns Paramiko SSH/SFTP connections and directory listings. `sites.py` stores named site profiles, and `site_dialog.py` edits them. `transfer.py` implements local-to-remote, remote-to-local, local-to-local, within-session remote-to-remote, and cross-session remote-to-remote copy operations. `batch.py` runs bounded parallel node tasks and checks move-source metadata. Work-node drop and delete actions in `window.py` choose the scope and pass explicit operations to that engine; `batch_dialog.py` remains in the codebase but has no visible entry point. `file_operations.py` implements rename, directory creation, and deletion. `conflict_dialog.py` asks the user how to handle an existing file; `file_icons.py` provides file-type icons.

`remote.py` 管理 Paramiko SSH/SFTP 连接和目录列表。`sites.py` 保存具名站点资料，`site_dialog.py` 用于编辑资料。`transfer.py` 实现本地到远程、远程到本地、本地到本地、同一远程会话内及不同远程会话间的复制。`batch.py` 并行运行有限数量的节点任务并检查移动来源元数据。`window.py` 中的工作节点拖放和删除操作会选定范围，再向该执行逻辑传入明确操作；`batch_dialog.py` 暂留在代码库，但没有可见入口。`file_operations.py` 实现重命名、新建目录和删除。`conflict_dialog.py` 询问同名文件的处理方式；`file_icons.py` 提供文件类型图标。

The work-node file table starts a drag with only a worker token and absolute source paths. After a drop onto the local or jump pane establishes the destination, it asks whether to copy from the focused node or all connected nodes, checks resulting names for cross-node collisions, and starts direct SFTP transfers with up to four concurrent node tasks. `transfer.py` adds `_<alias>` only to each source root: before a file extension for files and after the full name for directories. Jump destinations open a separate jump SFTP connection per worker so concurrent writes do not share one client. In-app drops use existing overwrite prompts and per-node results. Work-node-to-Explorer dragging is deferred pending Windows integration that does not interrupt the drag. The source is never deleted.

工作节点文件表开始拖动时只携带节点标识和绝对来源路径。投放到本地或跳板面板、确定目标目录后，才询问从当前节点或所有已连接节点复制；程序检查不同节点的目标名称冲突，再以最多四个节点任务直接通过 SFTP 传输。`transfer.py` 只给每个来源顶层项目追加 `_<别名>`：文件放在扩展名前，目录放在完整名称后。跳板目标为每个工作节点另建独立跳板 SFTP 连接，避免并行写入共用客户端。软件内投放沿用同名覆盖询问和逐节点结果。工作节点拖到资源管理器的功能暂缓，等待不会中断拖动的 Windows 集成方式；来源不删除。

## Connections and jobs / 连接与任务

Direct connections use Paramiko. A saved-site jump opens an SSH `direct-tcpip` channel through the current site and then creates another Paramiko connection. An SSH-alias jump runs the jump site's OpenSSH client and opens a target SFTP subsystem. Multiple work-node alias sessions keep their own SFTP channels while the primary jump session stays open. Work nodes are assigned at most eight SFTP channels per jump SSH connection; extra jump connections are opened as needed using the current session credentials held in memory. The work-node browser merges cached listings at one path or shows a focused node; it also supplies selected file names and node scope to batch operations. It does not yet expose independent full views or inline editing for every node. Discovery combines explicit Host aliases from user/system OpenSSH config with all numbered hostnames in `/etc/hosts`, regardless of prefix. Only if that file provides no numbered hosts does it try bounded `getent hosts` queries derived from the jump hostname. The older sequential jump stack remains available for saved-site connections.

直连使用 Paramiko。经已保存站点中转时，程序通过当前站点打开 SSH `direct-tcpip` 通道，再建立另一个 Paramiko 连接。SSH 别名中转则运行跳板站点上的 OpenSSH 客户端，并打开目标的 SFTP 子系统。多个工作节点别名会话各自保持 SFTP 通道，同时主跳板会话保持连接。每条跳板 SSH 连接最多分配八条工作节点 SFTP 通道；需要时使用本次会话的内存凭据建立额外跳板连接。工作节点浏览器可合并同一路径的已缓存列表，或显示聚焦节点；还会向批量操作提供选中的文件名和节点范围。尚无每个节点独立的完整视图或行内编辑。节点发现结合了用户和系统 OpenSSH 配置中的明确 Host 别名，以及 `/etc/hosts` 中所有带编号的主机名，不限前缀。只有该文件没有编号主机时，才根据跳板节点名称限时运行 `getent hosts` 查询。原有逐级中转栈仍用于已保存站点连接。

`MainWindow._run` starts one `QThread` job for blocking SSH/SFTP and file work, and disables conflicting controls until it finishes. A multi-node copy or delete uses a thread pool of up to four node tasks inside that job. Jump-to-worker transfers open an independent jump SFTP connection per task; worker-to-worker transfers use the two existing independent worker sessions. Progress and per-node results return through Qt signals. File conflicts are serialized into GUI Overwrite, Skip, or Cancel dialogs. The window still has one top-level job slot, with no persistent transfer queue or transfer-task retry.

`MainWindow._run` 用一个 `QThread` 任务执行阻塞式 SSH/SFTP 和文件操作，并在完成前禁用可能冲突的控件。多节点复制或删除在其中使用最多四个节点线程。从跳板到工作节点的传输为每个任务建立独立跳板 SFTP 连接；工作节点之间的传输使用已有的两个独立工作节点会话。进度和逐节点结果通过 Qt 信号返回界面。同名文件冲突会串行进入 GUI 的覆盖、跳过或取消对话框。窗口仍只有一个顶层任务位，没有持久传输队列或传输任务重试。

File mutations pass a plain-language action description to `_run`, which starts an in-memory operation-log row and updates it on completion or error. Batch-result signals append per-node rows in the Files-tab result table; the operation log keeps one grouped summary per batch. A vertical `QSplitter` lets the user resize the shared log below the Files and Terminal views; a View menu action persists its visibility through `QSettings`. The log is capped at 300 entries and is not written to disk. It does not show API calls or Shell commands. SFTP and local APIs retain the actual conflict and safety behavior. In local-to-worker copies, the worker session receives bytes from local files; the jump filesystem is not a source.

文件修改向 `_run` 传入自然语言操作说明；该入口先新增一条内存日志，再在任务完成或报错时更新。批量结果信号在文件页结果表中逐节点新增行；操作日志对每批只保留一条归并后的汇总。日志在“文件”和“终端”视图下方共用，可通过纵向 `QSplitter` 调整高度；“查看”菜单中的勾选项通过 `QSettings` 保存显示状态。日志最多保留 300 条，不写入磁盘，也不显示 API 调用或 Shell 命令。实际冲突处理和安全行为仍由 SFTP／本地 API 负责。本地复制到工作节点时，工作节点会话直接接收本地文件字节，跳板文件系统不是来源。

Work-node terminal channels are assigned to jump SSH connections with a conservative four-channel budget per connection, also counting work-node SFTP channels on the primary jump transport. Additional authenticated terminal-only jump connections open no SFTP subsystem and close when their last terminal closes. If a channel is refused with SSH open failure code 2, the failed node is retried on a fresh jump connection with bounded attempts; failures remain visible. There is no application-level limit on Terminal Groups or terminal count; actual capacity still depends on the SSH servers and local resources. A newly connected group opens its Combined tab by default. Its Combined tab stays available while the group exists, and “Disconnect current group” closes only that group's sessions after confirmation.

工作节点终端通道按每条跳板 SSH 连接最多四条的保守额度分配；主跳板传输上的工作节点 SFTP 通道也计入额度。额外的已认证跳板连接专供终端使用，不打开 SFTP 子系统，并在最后一个终端关闭后释放。若服务端以 SSH 通道打开失败代码 2 拒绝连接，失败节点会换一条新跳板连接有限次重试；最终失败仍会显示。程序没有设置终端组数或终端数上限；实际容量仍取决于 SSH 服务器和本机资源。新连接的组默认打开联合视图标签；组存在期间该标签保持可用，“断开当前组”经确认后仅关闭本组会话。

Terminal connection setup runs through `_run` so opening a PTY does not block the GUI. Once connected, `TerminalManager` owns each channel and a Qt timer polls ready output without using `_job`; ordered background writes send keys typed directly in each output pane to its own channel. The terminal channels are separate from SFTP. Alias-node shells run jump-host OpenSSH with strict host-key checking and passwordless login. The output display renders common ANSI SGR colors, carriage-return and backspace line edits, and basic clear-screen sequences; full-screen cursor-positioning programs still need a terminal emulator.

终端连接建立过程使用 `_run`，打开 PTY 时不会阻塞界面。连接后 `TerminalManager` 持有各通道，Qt 定时器轮询已就绪的输出，不占用 `_job`；在各输出区域直接输入的按键通过有序后台写入发送到其对应通道。终端通道与 SFTP 分开。SSH 别名节点的 Shell 通过跳板节点 OpenSSH 建立，严格校验主机密钥并要求免密登录。当前输出界面能显示常见 ANSI SGR 颜色、回车与退格的行编辑以及基本清屏序列；依赖光标定位的全屏程序仍需完整终端仿真器。

## Storage and safety / 存储与数据安全

The planned final Windows release is a self-contained portable edition that runs after extraction without an installer or preinstalled Python. Keep packaging concerns separate from SSH/session logic and verify the bundle on a clean target system. An installer is optional and lower priority than the portable edition; no packaging implementation exists yet.

计划中的最终 Windows 发行形式优先为自包含的免安装绿色版：解压即可运行，目标机器无需安装器或预装 Python。打包相关逻辑应与 SSH／会话逻辑分离，并在干净的目标系统上验证。安装版可选，优先级低于绿色版；目前尚无打包实现。

Source runs keep sites outside the repository in the user's `NodeBridge/sites.json` under Qt's generic configuration location (Windows on this machine: `%LOCALAPPDATA%\NodeBridge\sites.json`). A frozen executable resolves the site file to `data/sites.json` beside the executable; no release bundle exists yet. Site files support plaintext, no-save, and master-password modes. The master mode derives a key with Scrypt and encrypts each password with Fernet; the salt and an encrypted verification token live in the version-2 site file. The master key remains in memory for the run. Local-pane visibility and its last successful directory use `QSettings`; an unavailable saved directory falls back to the home directory. Remote drag export from the primary site uses temporary local files removed at exit.

源码运行时，站点资料位于仓库之外、Qt 通用配置目录下的用户 `NodeBridge/sites.json` 中（本机 Windows 路径为 `%LOCALAPPDATA%\NodeBridge\sites.json`）。冻结打包的程序将站点文件定位到可执行文件旁的 `data/sites.json`；发行包尚未实现。站点文件支持明文、不保存及主密码模式。主密码模式用 Scrypt 导出密钥，并用 Fernet 加密每个密码；盐和加密的验证值保存在 v2 站点文件中。主密钥仅在本次运行时留于内存。本地面板显示设置及最近一次成功打开的目录使用 `QSettings`；保存的目录不可用时回到用户主目录。主远程站点拖出文件会使用临时本地副本，并在 NodeBridge 退出时清理。

Unknown or changed SSH host keys are rejected. Deletes require confirmation: remote deletion is recursive and permanent, while local deletion moves items to the Recycle Bin. The underlying move engine requires separate confirmation and is limited to one destination, but the current drag-and-delete UI does not expose it. It deletes the source only after the copy has no failures, skips, or cancellations and the source-tree metadata remains unchanged. Multi-node distribution and collection only copy; multi-source move is planned. Same-name regular files require a choice before replacement; replacement is staged before the original is replaced. Copying symbolic links and special files is currently rejected. Multi-node operations are not transactional: completed work remains after a later failure, and metadata checks are not content-hash verification.

未知或变化的 SSH 主机密钥会被拒绝。删除需要确认：远程删除递归且永久生效，本地删除移入回收站。底层移动执行逻辑另需确认，且仅支持一个目标，但当前拖放和删除界面尚未提供入口；复制没有失败、跳过或取消，并且来源目录树元数据未变化时才删除来源。多节点分发和汇集都只复制；多来源移动仍待实现。同名普通文件替换前需要用户选择，且先暂存新文件再替换原文件。目前不复制符号链接和特殊文件。多节点操作不具备事务性：后续失败不会回滚已完成内容，元数据检查也不等于内容哈希校验。
